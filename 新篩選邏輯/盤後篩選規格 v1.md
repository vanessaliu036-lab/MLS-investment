# MLS 盤後篩選規格 v1.0

> **這份文件是實作契約。** 下一個 AI 依此實作，不得自行增刪判定邏輯、不得放寬鐵律。
> 所有標「可調」的數字是預設值，可由 config 覆寫；未標「可調」的是硬規則，不可改。

---

## 0. 這份篩選器在做什麼（讀懂再寫）

**輸入時點**：每個交易日**收盤後**執行（約 15:00 之後，等 FinMind 當日籌碼到位）。
**輸出用途**：產出**「明日盤中觀察清單」**。今晚（D 日收盤）篩出的清單，是給 **D+1 日盤中** 使用。
**唯一有法人蓋章的一關**：盤中沒有三大法人資料，只有主動買賣（aflow）。因此清單品質**全靠這關守住**，門檻寧嚴勿鬆。

**鐵律（不可違反，全部繼承自既有系統）**
1. `NO_DATA` 永遠不等於 `PASS`。缺資料就明講，不得用資料缺失湊過關數。
2. 三態判定：`PASS` / `FAIL` / `NO_DATA`，絕不二態。
3. **盤後篩選不得把「今日漲跌幅」當入選條件**。今日已漲 = 明日追高；今日沒動但法人默默進 = 明日埋伏標的。今日漲跌僅作參考註記。
4. 欄位之間方向矛盾時**不猜、不美化**，一律降級或否決。

## 2. 資料來源與欄位契約

| 欄位 | 來源 | 型別 | 允許 None | 說明 |
|---|---|---|---|---|
| `code` | 池定義 | str | 否 | 股票代號 |
| `name` | 池定義 | str | 否 | 股票名稱 |
| `sector` | 池定義 | str | 否 | 族群標籤 |
| `inst_month_net` | FinMind 盤後 | int | 是 | 三大法人近月累計淨額（張），正=買 |
| `inst_streak` | FinMind 盤後 | int | 是 | 法人連續買/賣日數，正=連買 負=連賣 |
| `month_volume` | FinMind 盤後 | int | 是 | 近月累計成交量（張），供百分比門檻用 |
| `aflow_dir` | 前一日盤中 aflow | int | 是 | 主動買賣資金連續方向，正=連續流入日數 負=流出 |
| `close` | TWSE / FinMind | float | 是 | 收盤價 |
| `ma20` | 計算 | float | 是 | 20 日均線 |
| `ma20_slope` | 計算 | float | 是 | MA20 斜率，用於判是否下彎 |
| `sector_median_pct` | 池內計算 | float | 是 | 該族群成員當日漲跌中位數 |
| `today_pct` | TWSE / FinMind | float | 是 | 今日漲跌幅，**僅註記，不進判定** |

> **缺欄位處理**：任一必要欄位為 None → 該關回 `NO_DATA`。
> `inst_month_net`、`aflow_dir`、`ma20` 為核心欄位，缺任一者該檔無法進 T1/T2。

## 3. 硬否決（Pre-filter，任一成立即出局，不進任何梯隊）

在四關判定之前先跑。目的：擋掉派發股與口徑矛盾股。

### D1. 法人大幅淨賣否決
```
若 month_volume 可用（非 None）：
    ratio = inst_month_net / month_volume
    若 ratio < -0.03  → 否決（近月淨賣超過月量 3%，派發中）  # 可調: -0.03
否則 fallback 絕對張數：
    若 inst_month_net < -5000  → 否決  # 可調: -5000
```
> 優先用百分比，大小股一致。月量缺失才退回絕對張數。
> 此條擋掉畫面上 `-79,056張`、`-1,391張` 那類。

### D2. 方向口徑矛盾否決
```
若 inst_month_net < 0 且 inst_streak > 0  → 否決（近月淨賣卻標連買，資料衝突）
若 inst_month_net > 0 且 inst_streak < -2 → 否決（近月淨買卻連賣3日以上，衝突）
```
> 不猜哪個對，衝突即砍。此條擋掉 `法人-486張/連買` `法人-67張/連買4日` 那類。

### D3. 資料完全缺失
```
若 inst_month_net 為 None 且 aflow_dir 為 None  → 否決（無任何資金證據）
```

> 否決的股票記入 `rejected_log`，附否決原因，供回溯。**不顯示在清單。**

## 4. 四關判定（通過 D 段的股票才跑；每關回傳 (state, evidence)）

順序：市場 → 技術 → 資金 → 抗跌。與既有 funnel.py 一致。

### 關 1｜市場面 `gate_market`
```
輸入: sector_median_pct
若 sector_median_pct 為 None → NO_DATA "族群強弱未取得"
若 sector_median_pct < -1.0  → FAIL   "族群中位 {x}% · 弱勢"   # 可調: -1.0
否則                          → PASS   "族群中位 {x}% · 非弱勢"
```

### 關 2｜技術面 `gate_tech`
```
輸入: close, ma20, ma20_slope
若 close 或 ma20 為 None → NO_DATA "日K/均線未取得"
若 close < ma20          → FAIL    "收盤未站上 MA20"
若 ma20_slope < 0        → FAIL    "MA20 下彎"
否則                     → PASS    "站上 MA20 且未下彎"
```
> 李佛摩六點**不列為硬門檻**（合格率過低會長期空手），僅作加分註記，寫入 evidence 不影響 state。

### 關 3｜資金面 `gate_money`（含方向一致性閘 — 本規格核心新增）
```
輸入: inst_month_net, inst_streak, aflow_dir
若 inst_month_net 為 None → NO_DATA "法人近月未取得"

# 力道/持續性門檻（二擇一）
strong = (inst_month_net >= 2000) or (inst_streak >= 2)   # 可調: 2000 / 2

# 方向一致性：法人近月方向 與 aflow 方向 取號
sign_inst  = sign(inst_month_net)
sign_aflow = sign(aflow_dir) if aflow_dir 非 None else 0

若 not strong → FAIL "力道不足(近月{net}張/連{streak}日)"
若 aflow_dir 為 None → PASS(降級) "法人正向但aflow未餵入,僅法人單證據" [degraded=True]
若 sign_inst == sign_aflow → PASS "法人與主動買賣同向"
否則                        → FAIL "背離:法人{net}張 但主動買賣反向,待確認"
```
> 這關擋掉「法人賣、主動買、股價漲」的背離股。同向才是真資金停泊。

### 關 4｜抗跌面 `gate_resilience`
```
輸入: chip_alignment ('green'三層一致 / 'yellow'長中一致 / 'red'不一致)
若 chip_alignment 為 None → NO_DATA "籌碼共振未取得"
若 chip_alignment == 'red' → FAIL   "籌碼🔴三層不一致"
否則 (green/yellow)        → PASS   "籌碼共振{🟢三層/🟡長中}一致"
```

## 5. 梯隊裁定 `classify`

```
n_nodata = 四關中 NO_DATA 數
n_pass   = 四關中 PASS 數
n_fail   = 四關中 FAIL 數

# 鐵律: 任一 NO_DATA 不進 T1/T2
若 n_pass == 4 且 n_nodata == 0        → T1  第一梯隊(四關全過)
若 n_pass == 3 且 n_fail == 1 且 n_nodata == 0 → T2  第二梯隊(差一關,差的是FAIL)

# T3 降級層(可用 config 開關關閉: enable_t3 = False)
若 enable_t3 且 n_pass == 3 且 n_nodata == 1 且 n_fail == 0:
                                         → T3  降級觀察(三關過,一關缺資料)
                                            部位上限強制砍半,清單標示缺口關名

否則                                     → OUT 淘汰(不顯示)
```

> **T3 是本規格唯一動到「寧可空手」立場的地方。**
> 它不違反鐵律：NO_DATA 仍不算 PASS、不進 T1/T2。
> 目的是資料源未接滿時系統仍能運作。若堅持嚴格空手，設 `enable_t3 = False` 即回到純三態。

## 6. 輸出 Schema

每檔輸出：
```json
{
  "code": "6182",
  "name": "合晶",
  "sector": "晶圓材料",
  "tier": "第一梯隊 | 第二梯隊 | 降級觀察",
  "diff_gate": "技術面 | null",
  "degraded": false,
  "position_cap": 1.0,          // T3 為 0.5
  "gates": [
    {"name":"市場面","state":"PASS","evidence":"..."},
    {"name":"技術面","state":"PASS","evidence":"..."},
    {"name":"資金面","state":"PASS","evidence":"..."},
    {"name":"抗跌面","state":"PASS","evidence":"..."}
  ],
  "note_today_pct": "+2.1%",    // 僅註記,不參與判定
  "status": "待驗證"            // 明日盤中驗證前的固定狀態
}
```

清單分三組回傳：`tier1` / `tier2` / `tier3`。`OUT` 與被否決者不回傳，另存 `rejected_log`。

**族群集中度上限**：單一族群在最終清單（t1+t2+t3）佔比不得超過 40%。超過時，該族群內按 `inst_month_net` 由大到小保留，其餘降入候補。  # 可調: 0.40

## 7. 給實作者的約束清單（不可違反）

1. 不得因「湊數量」把 NO_DATA 當 PASS。清單可以是 0 檔，0 檔是合法輸出。
2. 不得把 `today_pct` 寫進任何 gate 的判定分支。
3. D 段硬否決必須在四關之前執行，否決者不進四關。
4. 資金面方向一致性閘（關 3）不可簡化為「只看法人」或「只看 aflow」。
5. 族群強弱用中位數，不得用平均或檔數。
6. 每檔的每一關都要留 evidence 字串（人話證據），供逐關回溯。
7. 所有否決／降級都要記 log，可反查為何某檔沒進、某檔進了哪一層。

## 8. 預期產出量（驗收基準）

- 平常日：t1+t2+t3 合計約 **3–8 檔**
- 族群強勢日：約 **10–15 檔**
- 全market弱勢日：可為 **0 檔**（合法，不補位）

若某日輸出 30+ 檔或 0 檔持續多日，代表門檻或資料源異常，須告警而非靜默輸出。
